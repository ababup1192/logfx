## Faster — a line costs about a third of what it did

Nothing about the API changed, and **no byte of the emitted JSON changed**. This is only the
rendering: `toJsonLine` used to build a `Util.Json.Json` of its own for every key and every value
and run the standard encoder over each one, and it ran a `\p{Cntrl}` regular expression over every
string on the way. It now writes the characters straight into a builder, dropping the control
characters and escaping in the same pass, and appends a string whole when it has nothing to escape.

Measured with `make bench` on the same machine, fastest round of seven, 20,000 iterations each:

| | 0.3.0 | 0.3.1 | |
|---|---:|---:|---|
| One line, emitted as JSON | 6,725 ns | **2,034 ns** | −70% |
| Rendering that line | 6,699 ns | **1,936 ns** | −71% |
| Rendering `time` / `severity` / `message` alone | 2,525 ns | **654 ns** | −74% |
| The effect and handler path, no rendering | 596 ns | 611 ns | unchanged |
| A line the threshold drops | 176 ns | 177 ns | unchanged |
| `Logfx.exception` | 7,014 ns | 7,135 ns | unchanged |

The paths that were not touched did not move, which is what says the rest is real.

`test/TestLogfx.flix` gained `testToJsonLineMatchesTheJsonEncoder`: 27 records — quotes,
backslashes, text outside ASCII, a surrogate pair, control characters in and out of nested values,
both infinities, `NaN`, an integer past `Int32`, empty lists and objects, a time before 1970 — are
rendered both by `toJsonLine` and by a reference built only from the public `valueToJsonString`,
and compared byte for byte. A writer that drifts from the standard encoder fails that test.
