## Faster — a line costs a quarter of what it did

Nothing about the API changed, and **no byte of the emitted JSON changed**. Four things about how a
line is written did:

- `toJsonLine` used to build a `Util.Json.Json` of its own for every key and every value and run the
  standard encoder over each one. It now writes the characters straight into a builder.
- It ran a `\p{Cntrl}` regular expression over every string. Dropping the control characters and
  escaping now happen in the same pass, and a string with nothing to escape is appended whole.
- `time`, `severity` and `message` are written into that same builder rather than assembled as
  strings first. `timeText` on its own is no faster — the saving is the string that no longer
  exists between the calendar arithmetic and the line.
- The three head keys were removed from the fields with three `Map.remove` calls on every line,
  rebuilding the map three times to remove, almost always, nothing. Three comparisons decide it
  now.

Measured with `make bench` on the same machine, fastest round of seven, 20,000 iterations each:

| | 0.3.0 | 0.3.1 | |
|---|---:|---:|---|
| One line, emitted as JSON | 6,725 ns | **1,543 ns** | −77% |
| Rendering that line | 6,699 ns | **1,410 ns** | −79% |
| Rendering `time` / `severity` / `message` alone | 2,525 ns | **463 ns** | −82% |
| The effect and handler path, no rendering | 596 ns | 604 ns | unchanged |
| A line the threshold drops | 176 ns | 166 ns | unchanged |
| `Logfx.exception` | 7,014 ns | 7,166 ns | unchanged |
| `Logfx.timeText` on its own | 350 ns | 344 ns | unchanged |

The paths that were not touched did not move, which is what says the rest is real.

`test/TestLogfx.flix` gained `testToJsonLineMatchesTheJsonEncoder`: 27 records — quotes,
backslashes, text outside ASCII, a surrogate pair, control characters in and out of nested values,
both infinities, `NaN`, an integer past `Int32`, empty lists and objects, a time before 1970 — are
rendered both by `toJsonLine` and by a reference built only from the public `valueToJsonString`,
and compared byte for byte. A writer that drifts from the standard encoder fails that test.

## Also

- `bench/` and `make bench` are new: what one line costs, compared against
  `docs/bench/baseline.json`. It does not run in CI, where the timings move by more than the
  changes worth catching.
- The README says how to carry a span onto another thread. An effect handler does not cross a
  thread, but a `Sink` is a value and does, so the span rides in `Sink.enrich`.
  `examples/server` now spawns background jobs that way.
