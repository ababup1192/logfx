## Changed — the shape of `exception.stacktrace`

Frames are now written `class.method(file:line)` instead of the JVM frame's own `toString`, which
spelled the file as the **absolute path it was compiled from**. Frames that carry no line number
(`Clo$…invoke`) are dropped, because they cost bytes without saying where you are.

Measured on a line built from a caught `SQLException`:

| | 0.2.1 | 0.3.0 |
|---|---|---|
| The whole line | 1490 bytes | 516 bytes |
| `exception.stacktrace` | 1196 bytes (80% of the line) | 222 bytes (43%) |
| Absolute paths in it | 8 | 0 |

Nothing readable was lost — the dropped frames had no line number, and the build machine's
directory layout is not information about your failure. It was also the one line that multiplies
on the day the database falls over.

**If you read `exception.stacktrace` in Loki or Grafana, this is the field whose shape changed.**
No other field moved, and no API changed.
