## Faster again — and the README now says what a line costs

0.3.1 got a line down to 2,034 ns by writing the JSON straight into a builder instead of handing
every key and every value to the standard encoder. This takes the three things that were left.
As in 0.3.1, the API is unchanged and **no byte of the emitted JSON changed**.

- `time`, `severity` and `message` are written into the line's builder rather than assembled as
  strings first. `Logfx.timeText` on its own is no faster — what disappeared is the string that
  used to sit between the calendar arithmetic and the line, and the escape scan over three values
  already known to need none.
- `timeText` built its eight pieces with `String.padLeft` and interpolation. It writes digits now.
  A number too wide for its field, or a negative one, still goes through the old path, so the text
  is the same for every input.
- The three head keys were taken out of the fields with three `Map.remove` calls on every line,
  rebuilding the map three times to remove, almost always, nothing. Three comparisons decide it now.

Measured with `make bench` (Darwin arm64, fastest of seven rounds of 20,000):

| | 0.3.0 | 0.3.1 | 0.3.2 | |
|---|---:|---:|---:|---|
| One line, emitted as JSON | 6,725 ns | 2,034 ns | **1,543 ns** | −77% from 0.3.0 |
| Rendering that line | 6,699 ns | 1,936 ns | **1,410 ns** | −79% |
| Rendering `time` / `severity` / `message` alone | 2,525 ns | 654 ns | **463 ns** | −82% |
| The effect and handler path, no rendering | 596 ns | 611 ns | 604 ns | unchanged |
| A line the threshold drops | 176 ns | 177 ns | 166 ns | unchanged |
| `Logfx.exception` | 7,014 ns | 7,135 ns | 7,166 ns | unchanged |

The paths that were not touched did not move, which is what says the rest is real.

## The README says what a line costs

There was no number anywhere in it. There is now a section with the table above, and with the two
things worth reading out of it: a dropped line costs a ninth of an emitted one, which is why the
fields of a `debugWith` go behind a thunk; and `Logfx.exception` costs more than four ordinary
lines, so it belongs on the failure rather than on the request.
